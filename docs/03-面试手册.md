# 面试手册 · 20 个高频追问与讲法

> 面试官不关心你会不会用某个 API，只关心三件事：
> **① 你理不理解底层链路 ② 出问题时你怎么定位 ③ 你知不知道自己方案的边界。**
> 下面每题给「回答骨架」+「能指向的代码」，别说空话，直接指向具体类。

## 一、项目定位（先练 3 分钟开场）

**推荐讲法（STAR 压缩版）**：

> 这是一个面向隧道/高速监控中心的 AI 应用，用 Spring Boot 3.5 + Spring AI 1.1.8 实现。
> 我做它要解决的是「Java 后端如何系统性地补齐 AI 应用能力」，所以刻意覆盖四条链路：
> 手写 RAG 六步、Tool Calling 实时数据、结构化事件工单、多轮会话记忆。
> 工程上配了 20 条评估集、增量入库、来源溯源、密钥守卫和 CI 密钥扫描。
> 最有价值的不是功能，是过程中处理了几个真实的坑，比如智谱端点的 `/v1` 路径问题、
> 以及 force 重建时旧块没删导致重复召回。

**别这么讲**：「我用 Spring AI 做了个 chatbot」——一句话把项目贬到 Demo 级。

## 二、RAG 链路

**Q1. 讲一下 RAG 完整流程。**
加载 → 切块 → 向量化 → 入库（离线）；问题向量化 → Top-K 检索 → 拼 context → LLM 生成 → 溯源（在线）。
代码：`KnowledgeBase.ingest()` / `RagService.ask()`。主动补一句「向量化由 `store.add()` 内部触发，业务代码不直接碰向量」。

**Q2. 为什么中文不能按固定字符硬切？**
会把「CO 70ppm 关闭入口」拦腰截断，召回半句话导致漏关键数值。本项目先按 `。！？；` 分句，再累积到 chunkSize。代码：`ChineseTextSplitter`。

**Q3. chunkSize 和 topK 怎么定？**
没有通用最优值。做成配置项（`app.rag.*`），用评估集跑命中率基线，改一个数再跑一次对比。
主动说权衡：块大上下文全但噪声多；topK 大覆盖全但稀释注意力 + cost 上升。

**Q4. 检索「查不到」和传统数据库查不到有什么区别？**
向量检索永远返回最像的 K 条，哪怕全不相关。所以必须做相似度阈值 + 提示词明确允许拒答 + 返回 `refused` 标记。
**这题答不上来，基本会被判定为只调过 API。**

**Q5. 怎么防幻觉？**
三层：① `temperature=0.1` 压随机性 ② System Prompt 禁止用常识补数字、要求原样引用 ③ context 不足时明确拒答。
再加来源溯源，让人能核对。要主动承认：**RAG 不消除幻觉，只是把凭空编变成有据可查。**

**Q6. 为什么手写检索不用 QuestionAnswerAdvisor？**
教学与可控性：需要自定义来源标记、context 长度预算、拒答判定。生产可一行换 Advisor，能力等价。
给出 `docs/01-架构与链路.md` 里的对照代码。

**Q7. 增量入库怎么做的？有什么坑？**
sha256 指纹存 `data/ingest-state.json`，未变化跳过。**坑**：force 重建时若状态被清空，会跳过删旧块，导致新旧内容同时被召回。修法是 `delete(旧id)` 必须无条件执行。id 设计成可推导的 `文件名#序号`。

**Q8. 换 embedding 模型会发生什么？**
维度不一致直接报错或结果错乱，磁盘上的旧向量全部失效，必须 `force=true` 全量重建。这是配置变更里最危险的一个。

## 三、Agent 与结构化输出

**Q9. RAG 和 Agent 的区别？**
RAG 是固定流水线（必定检索再生成），Agent 是模型自主决策（要不要调工具、调哪个、调几次）。
代价是延迟和不确定性上升，所以简单问答走 RAG。

**Q10. 什么数据该放向量库，什么该做成 Tool？**
静态知识（预案、规则、阈值）放向量库；动态事实（此刻 CO 值、当前封路状态）做成 Tool。
把实时数据塞进向量库是反模式：刚入库就过期，还污染检索。代码：`TunnelTools` 注释里写得很清楚。

**Q11. 工具描述为什么重要？**
`@Tool(description)` 是 LLM 判断「何时调用」的**唯一依据**。描述写错或过时，表现就是该调不调、不该调乱调。
这是「注释变成生产逻辑」的典型例子，改实现必须同步改描述。

**Q12. 结构化输出的原理？失败怎么办？**
`BeanOutputConverter` 由 `IncidentReport` record 生成 JSON Schema 附到提示词，再把返回文本反序列化。
模型不保证返回合法 JSON，生产要降级：`.content()` + 解析 + 重试，或启用 response-format。字段越多遵从率越低。

**Q13. ChatMemory 有什么局限？**
内存实现，按 conversationId 隔离，重启丢失、多实例不共享 —— 和 Session 放内存是同一个权衡。
生产换 Redis / JDBC 的 `ChatMemoryRepository`。还要考虑窗口大小（本项目 20 条）与 token 成本。

**Q14. 为什么封路/疏散要 `needHumanConfirm=true`？**
AI 只给建议，不代替人下发生产指令。这既是安全设计也是责任边界；涉及人员安全的决策必须有人确认。
**主动讲这个，比多讲一个 API 更能体现工程判断力。**

## 四、工程化与质量

**Q15. LLM 输出不确定，怎么测试？**
不写 `assertEquals`。分层：纯单元（切块/指纹）→ 评估集（20 条问题→期望关键词）→ 集成评估算命中率基线，默认 skip，显式开启才花 API 费用。

**Q16. 评估集本身怎么保证不是编的？**
`EvalCaseIntegrityTest` 强制每条正向用例的期望关键词能在声明的源文档里**逐字找到**，并检查覆盖 5 份文档、包含拒答用例。
「给测试本身写测试」——这题是加分项，多数候选人想不到。

**Q17. CI 怎么不依赖真实凭证？**
`ZHIPU_API_KEY=ci-dummy-key-not-for-api-calls`，纯单元测试不发起真实调用；`KeyGuard` 只校验非空。
另外跑 gitleaks 全历史扫描 + 检查 `.env` 未入库。

**Q18. 密钥怎么管理？**
环境变量注入 `spring.ai.openai.api-key`，`.env` 在 `.gitignore`，`KeyGuard` 启动 fail-fast，
`SecurityGuardTest` 扫源码，`gitleaks` 扫 Git 历史。**主动说清这四道防线各自防什么。**

**Q19. 生产要改哪些地方？**（照着 `docs/04` 讲，别装作已经生产可用）
SimpleVectorStore 换 PgVector/Milvus（只改一个 Bean）；中文切块换语义切分 + Rerank + BM25 混合检索；
ChatMemory 外置；工具接真实监控 API；评估升级为 LLM-as-Judge；补限流、脱敏、审计、灰度。

**Q20. 你踩过最深的坑是什么？**（务必准备一个真实的）
推荐讲**智谱端点 `/v1` 路径**：Spring AI 1.1.x 默认拼 `/v1/chat/completions`，智谱 v4 没有这段，
启动不报错、第一次提问才 404；而且 1.1.x 的属性名带 `options`，照抄当前 2.x 官网文档会**静默失效、悄悄用默认模型**。
排查方式是先脱开框架，用 curl/Python 直接打端点确认协议，再回来看自动配置的属性元数据。
> 这题考的不是知识点，是「先验证假设再改代码」的工作方式。
